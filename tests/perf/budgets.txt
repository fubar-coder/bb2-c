# spec testing/performance-budgets): per command of tests/perf/bench the
# highest allowed cycles per call (bmod.vblmod: per frame), judged by
# results perf in the tests perf_NAME (ctest --preset perf).
#
#   COMMAND    PROGRAM.TEST, the loop TEST of tests/perf/bench/PROGRAM.bas
#   BUDGET     the measurement of the build that set it (the larger value
#              of two runs) plus 1 %, rounded up, plus 3 cycles; for a loop
#              that waits for the blitter or follows the frame (its
#              repeated runs differ by more than 1 cycle per call and by
#              more than that margin absorbs) "B~T": B the highest value
#              of at least five runs, T the tolerance, twice the spread of
#              those runs (rounded up), B + T the highest allowed value
#   TARGET     the original's value: the same program with the CD's
#              ACIDLIBS and DEFLIBS (target perf-original); the goal, not
#              checked ("-": none)
#   LOOP       the body of the loop
#
# A step that makes a command faster tightens its budget in the same
# commit; a budget that goes up is a decision named in the commit.

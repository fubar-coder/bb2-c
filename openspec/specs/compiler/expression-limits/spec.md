# compiler/expression-limits Specification

## Purpose

What size and depth of expression the compiler accepts, which error it reports beyond its limits, and what an expression needs of the compiler's memory and stack.

## Requirements

### Requirement: The limits of an expression stay those of the original
The compiler SHALL report "Expression too Complex" when an expression has more than 32 pending elements or an operator's right operand would need a register beyond d7, and "Precedence Stack Overflow" when it has more than 64 pending operators, at the same line as the previous commit's compiler.

#### Scenario: Too many pending operators
- **WHEN** a source has an expression with 65 nested brackets
- **THEN** the compile stops with "Precedence Stack Overflow" at that line

#### Scenario: Operand beyond d7
- **WHEN** a source has an expression whose operator would take its right operand from a register beyond d7
- **THEN** the compile stops with "Expression too Complex" at that line

### Requirement: The length of an expression does not use stack
An expression whose operators of one precedence follow each other SHALL compile with a stack use that does not grow with the number of operators.

#### Scenario: A long chain
- **WHEN** a source has a line, generated by a macro, with a sum of 1000 terms
- **THEN** it compiles on the compiler's own stack and the program prints the sum

### Requirement: The first of two errors is reported
When an expression contains two errors, the compiler SHALL report the one the previous commit's compiler reports, with its message and line.

#### Scenario: Illegal operator before an unknown function
- **WHEN** a source has `a$*2+nofunc{}`
- **THEN** the message is the one the previous compiler gives for it

### Requirement: An expression the memory cannot hold is an error
When the memory for an expression's tree cannot be had, the compiler SHALL stop with the compile error "Out of Memory" at the expression's line and SHALL NOT retry.

#### Scenario: No memory for a further block
- **WHEN** the system has no memory left for a further block of the expression's tree
- **THEN** the compile stops with "Out of Memory" at that line

# Proposal

## Why

Every program change needs `ctest --preset all` (about 5 minutes) and
`ctest --preset bug-orig` (about 23 minutes). Most changes touch a few
functions only, but nothing tells which tests execute them, so every
check runs everything. A record of which functions each test executes
makes it possible to run only the tests a change can affect while
working, and to see which code no test reaches. The feasibility studies
of 2026-11-05 showed that the host side supports gcov as it is, and that
`m68k-amigaos-gcc` can instrument blitz2 with `-finstrument-functions`
without giving up `-fbaserel` or Kickstart 1.3. User decisions of
2026-11-05:

- No foreign runtime: the measurement is a build variant of our own
  programs (volamos, an API-level AmigaOS runtime, was considered and
  rejected).
- The map from functions to tests is generated by a full coverage run,
  not committed.
- The full runs stay the acceptance for every program change; the
  selection is for the work in between.

## What Changes

- **Host coverage**: an option `HOST_COVERAGE` of the host build (gcov,
  like `HOST_SANITIZE`), with the coverage data of each host test kept
  apart.
- **Coverage variants of the compilers**: `blitz2` and `blitz2-ab3`
  built with `-finstrument-functions` in a build of their own (preset
  `amiga-cov`). A small C module records each called function in a
  bitmap and writes it to `TEST:` at the program's end, through
  `dos.library`, also on Kickstart 1.3. The normal build and its checks
  stay unchanged.
- **Collecting in the emulator**: the test runners create the coverage
  directory on `TEST:` and copy the bitmaps back after each test.
- **lcov as the one format, and the selection**: after the collection on
  the host every kind of coverage (gcov data, compiler bitmaps) becomes an
  lcov tracefile per test, readable by `genhtml`, editors and coverage
  services. A C tool reads the tracefiles of a coverage run and selects the
  tests for a `git diff` (changed functions, plus rules for headers, data
  and build files), writing a list for `ctest --tests-from-file`.
- **Later stage, with gcov**: TED and the Blitz libraries instrumented
  with gcov (lines and branches). For the libraries inside compiled
  programs, a coverage library whose finit routine writes their data,
  with a compiler option of the coverage configuration that always links
  it. Coverage of the Blitz source of compiled programs is a change of
  its own (`blitz-coverage`). This stage gets its own tasks after the
  first two work.

## Capabilities

### New Capabilities

- `testing/coverage`: which code a test executes - the coverage
  variants of the programs, the data each test leaves, and what is
  recorded where.
- `testing/test-selection`: the map from functions to tests and the
  choice of tests for a change.

### Modified Capabilities

None.

## Impact

- `host/CMakeLists.txt`, top-level `CMakeLists.txt` (option passed to
  the host project), `CMakePresets.json` (configure preset `amiga-cov`,
  test preset `coverage`).
- `programs/blitz2/CMakeLists.txt` (coverage variant), a new runtime
  module for the instrumentation (`shared/` or `tools/lib`-like place for
  Amiga code, to be decided in the design).
- The emulator runners: `tests/corpus/runner`, `tests/ab3/cli.cmake`,
  `tests/blitz2`, `tests/bug-orig`, `libs/tests` (create and collect the
  coverage directory).
- New tools in `tools/` with their logic in `tools/lib/` and host tests.
- README (how to run a coverage build and a selected test run),
  `TODO.md`.
- No change of results: the normal build's programs, libraries and the
  executables the compilers generate stay byte-identical; the coverage
  variants only add code to the compilers themselves.
